# Чистый берег V25 на Linux и сервере

Сборка рассчитана на Linux x86_64 и **процессор без видеокарты**. Интерфейс и веса V25 сохранены. Обработка по-прежнему использует окно 768×768, перекрытие 192 px, binary-max и существующие фильтры. На CPU автоматический батч равен 1; TTA увеличивает время обработки. Ориентир для сервера — 4 ядра, 8–16 ГБ RAM и свободное место под Docker и результаты. Фактическое время зависит от размера снимков и процессора; оно не измерялось на вашем сервере.

## Запуск Docker

Установите Docker Engine и плагин Docker Compose на сервере. Распакуйте весь архив, перейдите в каталог `clean-shore-linux` и выполните:

```sh
docker compose up -d --build
```

При первой сборке нужен интернет для Python-пакетов и базового образа. Модели уже находятся в `models/`, их скачивание при запуске отключено. Сборка использует CPU-варианты PyTorch 2.8.0 и torchvision 0.23.0. В контейнер не устанавливается CUDA.

По умолчанию порт доступен только на самом сервере: `http://127.0.0.1:8501`. Чтобы открыть приложение на своём компьютере через SSH:

```sh
ssh -L 8501:127.0.0.1:8501 имя_пользователя@адрес_сервера
```

После подключения откройте `http://127.0.0.1:8501` в браузере своего компьютера.

Для доступа из доверенной локальной сети скопируйте `.env.example` в `.env` и задайте `BIND_ADDRESS=0.0.0.0`, затем выполните `docker compose up -d`. Открывать: `http://адрес_сервера:8501`. Встроенной авторизации нет; для публичного доступа используйте reverse proxy с HTTPS и авторизацией либо VPN. За прокси нужно разрешить WebSocket и загрузку файлов нужного размера.

```sh
docker compose ps
docker compose logs -f --tail=100
docker compose down
```

Проверка файлов и реальный короткий прогон обеих моделей на CPU:

```sh
docker compose exec clean-shore python serve.py --check-only
docker compose exec clean-shore python serve.py --smoke-test
```

Статус `healthy` подтверждает доступность Streamlit; проверка нейросетей выполняется отдельной командой `--smoke-test`. После успешного старта сервис автоматически перезапускается при перезагрузке Docker. Пересборка после обновления: `docker compose up -d --build`.

## Где хранятся данные

- `models/` подключается только для чтения. Включены SegFormer V25, его конфигурация и YOLO11n. При старте проверяются SHA-256 весов.
- Именованный том `shore-data` хранит `/data/results/<идентификатор>/`: исходные фото, маски, карты вероятностей, правки и экспорт. Обновление контейнера или `docker compose down` не удаляет том. **Не используйте `docker compose down -v`, если результаты нужны.**
- Настройки обработки и текущий анализ живут отдельно в каждой браузерной сессии. Общие `.preferences.json` и `.current_run.json` в серверном режиме не читаются и не записываются. Работы разных браузеров автоматически не открываются друг у друга.
- После полного обновления страницы/завершения сессии текущая работа может исчезнуть из интерфейса; сохраненные результаты остаются на диске. До закрытия скачайте экспорт. Общая история пользователей и учетные записи в эту версию не входят.
- Администратор может выгрузить все результаты: `docker compose cp clean-shore:/data/results ./results-backup`. Доступ к тому дает доступ ко всем фотографиям.

В контейнер не копируются ваши старые результаты, настройки Windows, исходные DJI из прошлых анализов и локальные виртуальные окружения. Рабочий процесс контейнера не имеет прав root. Удаление старых работ выполняет администратор после резервного копирования; автоматической очистки нет.

## Linux без Docker

Нужен Python 3.11 и системные библиотеки OpenCV (для Debian/Ubuntu: `libgl1`, `libglib2.0-0`, а также пакет `python3-venv`). Из каталога приложения:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install torch==2.8.0 torchvision==0.23.0 --index-url https://download.pytorch.org/whl/cpu
.venv/bin/python -m pip install -r requirements.txt
CLEAN_SHORE_DATA_DIR="$HOME/clean-shore-data" sh Run.sh
```

`Run.sh` запускает приложение в текущем терминале. Для постоянной работы используйте Docker Compose или процессный менеджер. В этом режиме адрес по умолчанию `0.0.0.0:8501`; ограничивайте доступ сетевыми настройками сервера.

Переменные для `serve.py`: `CLEAN_SHORE_MODELS_DIR` — каталог моделей, `CLEAN_SHORE_DATA_DIR` — каталог результатов и кэшей, `PORT` — порт (8501), `MAX_UPLOAD_MB` — лимит одного файла (100). `CLEAN_SHORE_SERVER=1` включается автоматически. Для Compose внешний порт, адрес и лимит задаются через `.env`.

## Проверка этой поставки

Проверены: 27 тестов приложения, перенос путей хранения, отсутствие общего восстановления снимков, контрольные суммы весов, реальный CPU-прогон SegFormer и YOLO, а также синтаксис Docker Compose. Полная сборка и запуск Linux-контейнера в текущей среде не выполнены: Docker Engine не запущен. Перед эксплуатацией на сервере выполните приведенные команды `--check-only` и `--smoke-test`.
