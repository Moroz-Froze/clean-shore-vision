АУДИТ БЕЗОПАСНОСТИ «ЧИСТЫЙ БЕРЕГ»
Дата: 20.11.2026. Основа: OWASP Top 10:2025.
Объект: Docker CPU-поставка outputs/clean-shore-public-repo; исходная опубликованная версия v1.0.1, commit fca6974c97daf92eee8900ebb27b91f436924d9b.
Исправления включены в текущие исходники main. Архив релиза v1.0.1 остаётся прежним; для исправленной версии собирайте приложение из main.
Метод: анализ всех исходных Python-модулей, компонента HTML/JS, Docker/Compose и конфигурации; поведенческие тесты; Bandit; pip-audit; проверка официальных advisories. Это не внешний пентест развёрнутого Linux-сервера.

1. АРХИТЕКТУРА И ГРАНИЦЫ ДОВЕРИЯ
Python + Streamlit 1.67.0/Tornado; PyTorch 2.8, Transformers 4.57.1, SegFormer MiT-B2 V25; необязательный YOLO11n. PIL читает фотографии, OpenCV обрабатывает компоненты масок. Модель и детектор кэшируются через st.cache_resource и защищены локальными lock.
Базы данных, SQL/NoSQL-запросов, ORM, собственной системы пользователей, ролей и паролей нет. Данные находятся в файлах /data/results/<uuid>; веса — в /models. Версия для сервера не восстанавливает общие пользовательские настройки и предыдущие задания. Результат принадлежит сессии Streamlit, но это не полноценная модель владения данными с аккаунтами.
Вход: st.file_uploader, настройки, события JS-компонента, экспорт. Основные инфраструктурные маршруты Streamlit: /, /_stcore/stream (WebSocket), /_stcore/upload_file/..., /media/..., /component/..., /_stcore/health. Это маршруты фреймворка, не собственный REST API.
В браузере редактор отправляет ID объектов и ревизию. Сервер проверяет принадлежность ID текущему снимку и отклоняет устаревшие события. Пути к заданиям не принимаются как параметр URL. Временные имена формируются из индекса и очищенного basename; каждый анализ получает UUID.
Веса проверяются SHA-256, SegFormer загружается с weights_only=True, NumPy — с allow_pickle=False; Hugging Face работает offline/local_files_only. Это хорошие существующие меры; они не заменяют обновление библиотек.
Секретов API для инференса не требуется. Активных паролей и API-ключей в просмотренных исходниках не обнаружено. Полная история Git и секреты реального сервера не исследованы. .env не должен входить в Git или build context.

2. ПОДТВЕРЖДЁННЫЕ ПРОБЛЕМЫ И УСЛОВНЫЕ РИСКИ
Critical: подтверждённого эксплуатируемого Critical не установлено. Отсутствие находки не означает отсутствие уязвимостей.

S01 High — отсутствие аутентификации при внешней публикации (A01/A07).
Сейчас Docker публикует порт только на 127.0.0.1: это снижает внешний риск. Если изменить BIND_ADDRESS на 0.0.0.0 или поставить открытый прокси, любой посетитель получает доступ к функциям приложения и может занять CPU/память. Это не доказательство чтения чужой сессии.
Мера: подготовлен deploy/nginx.conf.example, Basic Auth на весь сайт включая загрузки/медиа/WebSocket, HTTPS, лимиты. Пока администратор не установит конфигурацию и пароль, проблема внешнего доступа не закрыта. Для аккаунтов и ролей нужен OIDC/SSO и явная авторизация данных.

S02 High — истощение ресурсов загрузками и повторным анализом (A06/A10).
Ограничение 100 MB на один файл не ограничивало число снимков, суммарную загрузку, площадь после декодирования и рост диска. Конкурирующие сессии могли ждать на модельном lock, удерживая память. Настройки CPU-модели могли создавать дополнительные экземпляры модели в кэше.
Исправлено: 32 файла, 256 MiB суммарно, 100 MiB на файл, 24 млн пикселей на снимок; только JPEG/PNG/TIFF, только один кадр; отказ до преобразования RGB. Глобальный admission lock не ставит новые анализы в неограниченную очередь. Для CPU-сервера параметры кэша модели канонизированы. Контроль свободного диска 2 GiB и допуска новых записей до 10 GiB результатов. Compose ограничивает CPU, память, PID и ротацию логов.
Остаток: файлы поступают в память Streamlit до проверки общего размера на кнопке; для сетевого входа необходимы proxy limits. Проверка размера хранилища — не жёсткая файловая квота, один кадр может превысить порог. Lock действует в одном процессе; несколько реплик требуют общей очереди и квот. Фильтрация/экспорт тоже расходуют ресурсы. Вредоносный декодерный CPU-hang нельзя надёжно остановить этим lock: для недоверенного публичного сервиса нужен отдельный worker с timeout.

S03 High — устаревший декодер Pillow 11.3.0 на границе пользовательского ввода (A03).
Официальный GHSA-wqgw-9xfh-qf2g описывает memory DoS при разборе TIFF/EXIF в Pillow <=12.3.0. Доступный вход принимает TIFF, поэтому риск релевантен. Другие предупреждения относятся к недоступным здесь форматам/API и не означают столько же атак на приложение.
Исправлено: Pillow==13.0.0; Image.open(..., formats=('JPEG','PNG','TIFF')) не запускает распознаватели остальных форматов. Один запрет расширений не защищал от файла с подменённым именем. Совместимость проверена тестами и CPU smoke test обеих моделей. Сканер не нашёл advisories для Pillow 13.0.0 на дату проверки. Это не гарантия будущей безопасности декодеров.

S04 Medium — неполная защита CSV от формул (A05).
Ранее экранировалось только filename и только при прямом начале с =,+,-,@. Строка gps_status берётся из XMP; имя с пробелом/табом перед формулой обходило проверку. Получатель мог открыть такой CSV в табличном редакторе и запустить формулу/внешний запрос; это не RCE на сервере.
Исправлено: проверяются все строковые значения, пробельные/управляющие префиксы, полные Unicode-варианты операторов; числовые значения остаются числами, csv.DictWriter экранирует разделители и кавычки. Строки нейтрализуются апострофом. Нет универсальной гарантии для всех редакторов и повторного сохранения: импортировать CSV как текст, для машинной передачи предпочесть GeoJSON.

S05 Medium — подробности исключений посетителю и слабая диагностика (A09/A10).
Ранее str(exc) мог попасть в интерфейс и манифест, включая внутренние пути и детали библиотек. Streamlit показывал полные ошибки.
Исправлено: внутренние ошибки заменяются сообщением с ID; в лог идёт ID и тип, без пользовательских метаданных/исходного текста ошибки. Разрешены только заранее составленные сообщения InputRejected. client.showErrorDetails='none'.
Остаток: это минимальный журнал, а не полноценный аудит действий. Требуются метрики, корреляция с прокси, контроль 401/429/OOM/диска, доступ администраторов к логам. Нельзя записывать пароли, Authorization, фото и GPS в публичные логи.

S06 Medium — отсутствие политики хранения фотографий/GPS (A01/A04/A06).
Исходные файлы, вероятности, манифесты и ручные правки остаются в volume после окончания браузерной сессии. GPS в экспорте — заявленная функция, но чувствительная информация. Подтверждённой общедоступной раздачи /data не установлено; человек с доступом к Docker/volume видит данные.
Мера: добавлен admission limit диска; автоматическое удаление не включалось, чтобы не уничтожить пользовательские результаты. Нужны согласованный TTL, управляемое удаление завершённых заданий, права volume, шифрование диска и резервных копий. Не считать UUID или потерю браузерной сессии механизмом удаления данных.

S07 Medium — незакрытые предупреждения supply chain (A03/A08).
Первый прямой скан: 95 записей advisories в трёх пакетах; после объединения aliases это 59 групп Pillow, 8 PyTorch, 7 Transformers. Это не 95 подтверждённых уязвимостей данного приложения.
После обновления Pillow осталось 19 записей в PyTorch/Transformers (15 групп aliases). Большая часть требует чужих checkpoint/Trainer/conversion API, которые загрузчик фото не предоставляет; некоторые низкоуровневые операции также не используются. Нужна отдельная оценка каждой записи, она не заменена числом сканера. Чужие модели загружать запрещено; доверенные файлы защищены хэшем и read-only слоем образа.
Major-обновление PyTorch/Transformers не выполнялось вслепую: совместимость V25/YOLO должна быть проверена на новой паре torch/torchvision. Транзитивные зависимости и базовый образ не зафиксированы единым hash lock/digest. Нужны Linux SBOM, pip-audit и Trivy/Grype по собранному CPU-образу, подпись образа, Dependabot и обновление с регрессией метрик.

S08 Low — HTTP/TLS и заголовки зависят от развёртывания (A02/A04).
Прямой Streamlit использует HTTP. Для localhost/SSH-туннеля это ожидаемо, для публикации в интернете — риск перехвата данных/учётных данных. Подготовлен Nginx HTTPS с nosniff, SAMEORIGIN, no-referrer, no-store, HSTS, Permissions-Policy. CSP дан в Report-Only для проверки совместимости, не является активной защитой. Конфигурация не установлена и не испытана на реальном Nginx.
Cookie: собственного auth-cookie нет, Basic Auth работает через Authorization. XSRF-cookie должна оставаться доступной JS; принудительный HttpOnly на ней ломает Streamlit. Прокси ставит Secure и SameSite=Lax. Пустой cookieSecret удаляется при старте, чтобы Streamlit сгенерировал случайный; для стабильной подписи задавать длинный секрет локально. Его значение не включать в образ.

3. ЧТО ПРОВЕРЕНО БЕЗ ПОДТВЕРЖДЁННОЙ УЯЗВИМОСТИ
SQL/NoSQL injection: нет БД и запросов; нет поверхности для этой категории в текущем приложении.
XSS: unsafe_allow_html используется для локального CSS, локального SVG и статических фрагментов. Пользовательский ввод туда не конкатенируется. Редактор рисует через canvas, не вставляет имя файла в innerHTML. Наличие unsafe_allow_html само по себе не подтверждает XSS. CSP ещё не enforcing.
CSRF/CORS: обе защиты Streamlit по умолчанию были включены; теперь включены явно. Добавлены allowlist hosts/origins для локального запуска. XSRF не заменяет CORS-защиту WebSocket. За обратным прокси необходимо указать реальный домен, а не отключать защиты для устранения 403.
IDOR: внешнего задания по числовому ID/пути нет, UUID создаётся сервером; чужая сессия автоматически не восстанавливается. Доступ к media/download Streamlit не равен ACL на базе аккаунтов: URL результата следует считать capability-ссылкой и не передавать другим пользователям. Изоляция двух удалённых клиентов с известными URL на Linux не проверена.
SSRF: пользователь не задаёт удалённый URL. download_models.py обращается к фиксированному HTTPS GitHub URL на этапе сборки. Сообщение Bandit B310 не доказывает SSRF.
Command injection: нет shell=True и команд из пользовательского ввода. os.execv запускает фиксированный Python со списком аргументов.
Слабая криптография: SHA-256 используется для целостности, не для паролей; hardcoded пароль не найден. Timestamp/token редактора — защита от повторного события, не аутентификация. UUID — имя задания, не ключ шифрования.
Бизнес-логика: метры/геолокация приблизительны и контролируются настройками; сумма площадей не дедуплицирует перекрывающиеся фото. Это явно отмечено в экспорте; результат не использовать как точный геодезический расчёт или автономное решение по ЧС.

4. ПРИМЕНЕНИЕ НА СЕРВЕРЕ
1) Собирать текущие исходники main, а не старый архив v1.0.1. docker compose up -d --build. Веса и пороги модели не менялись.
2) Оставить BIND_ADDRESS=127.0.0.1. Не публиковать 8501 через firewall. Для личной работы использовать SSH-туннель; для группы — Nginx HTTPS + Basic Auth/SSO.
3) Скопировать deploy/nginx.conf.example в конфигурацию host Nginx, заменить shore.example.com и сертификаты, создать /etc/nginx/shore.htpasswd с bcrypt через htpasswd -cB /etc/nginx/shore.htpasswd username. Не использовать пароль в командной строке. Проверить nginx -t до reload. Basic Auth — только через TLS. Для многих пользователей предпочтителен OIDC с MFA.
4) Создать .env локально, chmod 600; задать длинный STREAMLIT_SERVER_COOKIE_SECRET, реальный STREAMLIT_SERVER_ALLOWED_HOSTS и STREAMLIT_SERVER_CORS_ALLOWED_ORIGINS. Не передавать .env в Git/архив/образ. Нет необходимости задавать ROBOFLOW_API_KEY.
5) Установить CPU/RAM/дисковые лимиты под сервер. Нужна жёсткая квота тома и политика TTL. Не удалять активные задания. После принятия политики организовать очистку завершённых заданий и мониторинг свободного места.
6) Защитить /data и backup, шифровать диск, запретить доступ контейнера к Docker socket/чужим каталогам, сохранить non-root/read_only/cap_drop/no-new-privileges. Ограничить исходящую сеть, runtime работает offline.
7) Проверить 401 без пароля для /, загрузок, /media и WebSocket; 403 для чужого Origin/Host, 429 при лимитах; cookie Secure/SameSite, отсутствие подробных traceback; отсутствие межпользовательского доступа по известной ссылке. Проверить фотозагрузку, редактор, export и повторное подключение браузера через HTTPS.
8) Перед интернет-публикацией построить Linux CPU-образ, выполнить полный dependency/container scan, сохранить SBOM, digest и результаты smoke/интеграционных проверок. На этом компьютере Docker Engine недоступен, фактическая сборка и nginx -t не выполнены.

5. ПРОВЕРКИ И ОГРАНИЧЕНИЯ
36 unittest прошли, включая 7 новых проверок входа/CSV/квот/занятости/ошибок. Новые проверки до исправлений падали на исходных проблемах. Повторный прогон с Pillow 13.0.0 прошёл. CPU smoke test загрузил проверенные V25 и YOLO и выполнил предсказание. Compose config --quiet прошёл; конфигурация Streamlit действительно читает enableCORS=true, enableXsrfProtection=true, showErrorDetails=none, enableStaticServing=false.
Bandit: предупреждения про фиксированный HTTPS URL, local_files_only Hugging Face, bind 0.0.0.0 внутри контейнера и execv фиксированного Python рассмотрены вручную; это не доказанные атаки. assert в smoke-test не используется как production security check. Тестовый token='a' не является паролем.
pip-audit: direct-before/after файлы воспроизводят конкретные проверенные версии; отдельный host snapshot не равен Linux-образу, CUDA wheel и CPU wheel могут по-разному сопоставляться сканером. Не заявляется отсутствие всех CVE.
Не проверены: действующий сервер, внешний доступ, реальный TLS/cookies/headers, обход proxy, масштабирование, Linux-декодеры, нагрузка, полный Git history, GitHub settings/CI permissions. Локальный desktop-вариант приложения не менялся.
